净利助手 v0.24.3

这一版只改「取数服务的开关」这一块，解决一个困惑：关掉之后还能不能开、关窗口会不会把桥也关了。

一、启动 / 重启按钮会跟着状态变
- 桥在跑：按钮是「重启用本程序的桥」
- 桥被关掉：按钮自动变成「启动取数服务」，不用关掉程序重开
- 已停时「关闭取数桥」按钮置灰，避免连点
- 状态行会明确写「已关闭」，并提示取数、核算、计划任务都会停

二、关掉桥的后果写在确认框里
- 界面里的运行、核算、报表都会用不了
- 定时计划任务也不会再跑
- 随时可以在「调试」页点「启动取数服务」再开起来

三、驾驶舱认得出「桥断了」
以前桥被关掉时，店铺区显示「还没识别到店铺」，会让人以为要重新登录店铺。
现在明确写「取数服务没连上」，并给一个「去调试页启动」的入口；
点运行时也不再甩一句「Failed to fetch」，而是提示去启动服务。

四、修一个一直报假成功的 bug
源码模式（用「启动净利助手.bat」直接跑）下，「重启桥」的命令拼错了：
`python bridge --force` 被 Python 当成脚本路径，必然失败，而界面还提示「已重启」。
现在源码和打包两种模式各用各的命令，并且执行完会真去探一次端口，
没起来就如实说「命令执行了，但取数服务没起来」。

更新方式
- 免安装版：解压覆盖（数据/配置/报表 都在程序目录里，先备份再覆盖）
- 安装版：直接跑新的安装包，会覆盖程序、保留 数据/配置/报表
- 更新后重启程序，并在浏览器扩展页点一次「刷新」
