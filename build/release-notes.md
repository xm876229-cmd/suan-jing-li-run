净利助手 v0.24.2

这一版把「界面」和「跑法」都重做了：首页变成驾驶舱，程序里能配多条定时计划，
启动只需双击一次；另外补了一整套断电/强杀后的自愈机制。

一、首页变成驾驶舱：一家店一张卡，一个总开关控制全部
以前 7 家店要在浏览器里点 7 次运行。现在：
- 总控模式：顶部勾选要跑的店（可全选）+ 选一次区间 → 点「运行勾选的」
- 单店模式：每张卡上各自选区间、各自点运行，互不影响
- 卡片上直接看得到：浏览器在不在线、跑到第几步、每步花了多久、卡在哪/为什么失败
- 进度分六步：商品SKU表 → 订单表 → 广告表 → 联盟佣金表 → 核算 → 出报表；
  进行中的那步显示「已等 X 分 Y 秒」，大店那 8 分钟终于能看出是在动还是死了
关键前提是「任务按店铺投递」：每家店一个任务、店铺写死，只有那家店的扩展能领。
以前是全局队列、谁先来谁拿走，7 个浏览器同时开着必然串店，而报表看起来完全正常。

二、计划任务：可以配好几条，区间只存规则不存死日期
导航「运营 → 计划任务」。每条自己定：
- 多久跑：每天 / 每周几 / 每月几号 + 几点
- 算哪段：周期（按月/按周/按天/最近7天/全部）× 哪一期（本期/上一期/前N期）
  × 截到哪天（整期 / 到今天 / 第 N 天）
- 跑哪些店、报表另存到哪、带不带公式
因为只存规则：「每月 1 号 09:00 + 上月 + 整期」明年、换台电脑都还对。
漏跑会记账（页面顶部提示 + 一键补跑），补跑用的是「当时该跑的那一刻」算区间，
11-01 漏的上月不会变成这个月。

三、启动合成一步
双击 jingli.exe：先出启动页（进度条 + 正在做什么）→ 桥就绪自动跳主界面并放大窗口。
起不来会在启动页写清原因，不再白屏发呆。
启动时会比对「端口上那个桥是不是本目录的」，是别的目录的程序就关掉重起。
原来的「启动桥.bat」改名「修复-扩展连不上时点我.bat」，正常运行已经用不到它。

四、断电/强杀之后，程序自己收拾残局
以前所有配置都是「先清空再写」，断电正好落在中间就留下半截 JSON，下次读不出来
静默退回默认值——费率、参数、计划全变回出厂设置，不报错，只是以后算的净利都不对。
现在：
- 所有配置/状态/成本表改成原子写（临时文件 → 落盘 → 原子替换），并保留上一版 .bak
- 每次启动自检：配置坏了用 .bak 恢复，连备份都没有就挪进「_损坏文件」再补默认值；
  清掉断电留下的临时文件；清掉早已死掉的合并锁；打不开的报表挪进「_隔离_日期」；
  日志过大自动轮转；抓包记录保留 30 天（避免把 C 盘占满）
- 报表/快照/安装包都改成「先写临时名再改名」，不会再留下打不开的半截文件
- 界面「调试 → 自检与修复」可以随时手动体检一次

五、两套逻辑打架的地方（会互相顶掉、重复跑）
- 扩展自带周/月定时和程序的计划任务同时开着会跑两遍 → 现在桥在线时以程序为准
- 计划任务队列原来 30 分钟过期，早上派的中午开电脑就作废 → 改为 12 小时有效
- 同一家店可能开成两把锁（shop_id / 别名 / 目录名）→ 统一后再加锁
- 计划和旧的「自动运行」配置串味（报表目录、公式开关）→ 以计划为准
- 扩展没刷新时界面是新的、跑的代码是旧的 → 店铺卡片会显示「扩展 x.y.z 待刷新」
- 两个程序同时启动时守护进程互相抢端口死循环 → 先看端口健康，连续失败 6 次就停下说原因

六、其他修复
- 成本表里「1,234.50 / ¥12 / 12 元」这类写法会让整张表导不进来 → 现在能认
- 表格正被 Excel/WPS 打开时报一串 WinError → 改成「读不了 xxx：可能正在 Excel 里打开」
- 报表下载接口只能读报表目录里的文件
- 店铺名带 / : * 时报表文件名非法 → 一并净化
- 上传落盘补 fsync，避免断电后出现「文件名在、内容是空的」表

更新方式
- 免安装版：解压覆盖（数据/配置/报表 都在程序目录里，先备份再覆盖）
- 安装版：直接跑新的安装包，会覆盖程序、保留 数据/配置/报表
- 更新后重启程序，并在浏览器扩展页点一次「刷新」
- 第一次打开会检查上次是否异常退出，正常情况下「调试 → 自检与修复」显示"一切正常"
