## 订单下载链路（一整天踩出来的，v0.24.22 → 0.24.32）

真机上「大店订单导出」一直"生成中"，逐层剥开是四个独立问题：

1. **后台 fetch 卖家后台 = Failed to fetch**：补订单的 `export_record/get` / `order/download`
   原来在扩展后台发，MV3 后台是扩展源，一律被按跨域挡。→ 搬进页面（`runInPage`）。
2. **页面被自己关了**：每轮结束 `closeAllAutoTabs()` 全关，下一分钟只能"现开现用"，
   页面还在加载就注入必失败。→ 有待补时按 host 保留页面（`closeAllAutoTabs(keepHosts)`）。
3. **文件地址也在卖家域名下**：`download_url` 是 `seller-xx.tiktok.com/easesafe/...`，
   不是 CDN。后台 fetch 同样被挡。→ `fetchBytesInTab()`：页面里整份读进内存，
   按 4MB 分块（base64）搬回后台。**必须固定同一个 tabId**，换标签 = 缓存丢失。
4. **抢同一个标签页**：`runOrders` 开头先补订单，与正在导航的页面打架，
   订单步骤卡死 4 分钟；桥 12 分钟重派又叠一轮。→ 跑任务时不再补订单；
   闹钟补订单有 running 就让路；桥重派前查队列/进度。

配套：
- `waitRecord(…, 12, …)` 只等 48 秒 → 45 轮（3 分钟），文件一好立刻返回。
- 待补核算只认**新落地**的订单表（`_orders_fresh`，mtime ≥ 待补登记时刻）。
  原来只要有订单表就算，拿别的月份算出 `GMV 0 / 净利 -93212` 的废报表。
- 同一区间 20 分钟内已排过，不再建导出任务：一上午反复重派把平台队列堵死，
  4 家店 20 多分钟一个文件都不出（正常店 90 秒出）。

## 广告表币种（0.24.49，实测后定型）

- **平台导出的 `Currency=LOCAL` 指「广告账号本位币」，不是店铺本地币。**
  DXM 实测：后台 12,450.49 **USD**，导出写 LOCAL；当成 MYR 直接算 → 广告费少 4 倍、净利虚高 3.8 万。
- 判定顺序（`loader._ads_rate_to_local`）：
  1. 空/LOCAL/RM/等于本地币 → 1.0（不换）
  2. USD → usd_to_local
  3. 其它代码 → 交叉汇率 `rates[本地] / rates[该币]`（汇率表来自 fx.last_rates()，CNY 基准）
  4. 查不到 → 返回 None，金额计入 unknown，异常页明写「按 0 计，净利会偏高」
- 设置位置：费率页每国「广告表币种」输入框（留空=自动识别；LOCAL=不换；USD/THB/…=按该币）。
  存在 `rates.json → countries.<国>.ads_currency`。
- **坑**：`Params` 是显式构造的 dataclass，新字段必须同时加到类定义和 `load_rates` 里，
  否则 `getattr(params,"ads_currency","")` 永远是空，界面存了也不生效。
- 兜底：广告费 > GMV 60% 时，报表口径页第一行红字提醒「币种可能选错了」。

## 数据源不能认错（0.24.50）

- **根因**：`loader._pick_latest` 在「没有任何一份覆盖报表区间」时，退回**最新那份**

## 0.24.56：三条打架 + 一个根因（2026-11-04 14:05）

- **打包版 stdout 是空的**：`--windowed` → 子进程 `sys.stdout` 为 None，
  `jingli.exe run --json` 一个字节都写不出来（`_run_calc_cmd` 返回 0 字）。
  后果：桥的自动补算拿不到摘要 → 历史没记、日志说「解析失败」。
  修法：新增 `--json-out <文件>`，核算收尾把摘要写文件；桥优先读文件、
  读不到才退回解析 stdout。`/run` 和补算两条路都改了，临时文件用完即删。
- **复用订单被新落地校验挡住**：同一天第二次跑同一区间，扩展复用上午的表 →
  mtime 旧 → `/run`（auto）判「订单还没生成」→ 红叉。修法：`reused` 含「订单」时跳过 mtime 校验。
  防呆保留：不带 reused 时仍要求新落地（已实测：旧订单表 → ok:false + pending:true）。
- **等订单被标成失败**：扩展收到「订单还没落地」类错误 → 标 skip + 登记待补（以前一律 fail）。
- **同一份表算两遍**：`/run` 成功后撤掉该店待补条目（DXM 13:46 就是算了两次）。
- **崩溃弹窗**：`_report_crash()` 把堆栈写 `数据/日志/异常_*.log`，只弹一句人话。
- 实测：复用+auto 3.5 秒出表且写历史；待补补算写历史 ✓；防呆仍生效 ✓。
- 已发 GitHub v0.24.56，本地/远程哈希一致。

## 0.24.61：带公式报表循环引用（2026-11-04 15:41）

## 0.24.64：拿错月份的数据（2026-11-04 17:30）⚠ 严重

- **现象**：7 月计划里 PHT-W1(LR Stationery) 收件箱只有 8 月广告表，
  却算出了 7 月报表，广告费 228,601 = 8 月表 3,602.16 USD × 63.46（一分不差）。
  净利从 405,335（错）—— 实际上这个数也不可信，报表已删。
- **两个漏点**：
  1. `loader._pick_latest()` 开头 `if len(items) <= 1: return items` —— 只有一份时
     **直接返回，完全不校验区间**。之前修的「无覆盖就不用」被这条捷径绕过。
  2. `loader._merge_aggregate()` 的 `if covering:` 无覆盖时 keep 保持全部 → 合并进来。
- **修法**：删掉捷径（只保留 `if not items`）；`_pick_latest` 一份也校验区间；
  `_merge_aggregate` 无覆盖时 return []（仅当有能读出区间的表，读不出仍按全部用）。
  验证：PHT-W1 算 7 月 → 「数据不全，不出报表：缺 广告表」；PHT-M2 → 正常 -21,463。
- **GMV Max 账户取不到广告表**（Your-Self / LR Stationery，都是 PH）：
  - 根因 1：`onAds` 只按 URL 判断 `ads-creation` → 页面被渲染成卖家首页也判成"已在广告页"
    → 不点侧边栏 → 找不到导出按钮。新增 `hasAdsPanel()`（读页面文字找 GMV Max/广告计划…）。
  - 根因 2：GMV Max 面板的导出是**图标**（右上角下载小图标，无文字），
