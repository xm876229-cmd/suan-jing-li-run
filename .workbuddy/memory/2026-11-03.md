
## v0.24.22 联盟佣金真因：时区偏移符号

- **现象**：7 家店联盟佣金全失败，接口 `16048002 invalid timezone offset`，
  页面导出兜底也报「拦截器记录 0 条 / 没在导出接口的响应里找到文件地址」。
- **真因**：平台只认**东为正**（东八区 28800）。`src/auto_run.normalize_range`
  写成 `-int(off.total_seconds())` → -28800 → 平台拒。抓包里平台自己发的是 28800。
  - 修：`auto_run.py` 改东为正；扩展 `runAffiliate` 加兜底（桥给的和本地不同号就用本地）。
  - 实测：Crochet lover(PH) 联盟 → done，29 个商品；净利 61,115 → 43,132（虚高 1.8 万被扣回来）。
- **注意**：联盟走的是 `runSpecTask` → `POST /spec` → `配置/api_specs.json` 的
  `tasks.affiliate`（步骤「商品维度佣金」，body 里 `{{tzOffset}}`/`{{startTs}}`）。
  所以 Python 侧 tz 一改，这条主路就通；扩展里 `pagePullAffiliateProducts` 是另一条。
- **联盟导出兜底仍未修**：`export_task/create` 只回 `task_id`，地址要问 `export_task/list`，
  拦截器截不到 URL 是必然。宁可报错也不算错，先不动（要改就得核对 task_id 匹配）。

- 错字 `战斧浏览器` → `浏览器`（ui.py 3 处 + app.py 1 处）。

## 订单下载链路（一整天踩出来的，v0.24.22 → 0.24.32）

真机上「大店订单导出」一直"生成中"，逐层剥开是四个独立问题：

1. **后台 fetch 卖家后台 = Failed to fetch**：补订单的 `export_record/get` / `order/download`
   原来在扩展后台发，MV3 后台是扩展源，一律被按跨域挡。→ 搬进页面（`runInPage`）。
2. **页面被自己关了**：每轮结束 `closeAllAutoTabs()` 全关，下一分钟只能"现开现用"，
   页面还在加载就注入必失败。→ 有待补时按 host 保留页面（`closeAllAutoTabs(keepHosts)`）。
3. **文件地址也在卖家域名下**：`download_url` 是 `seller-xx.tiktok.com/easesafe/...`，
   不是 CDN。后台 fetch 同样被挡。→ `fetchBytesInTab()`：页面里整份读进内存，
   按 4MB 分块（base64）搬回后台。**必须固定同一个 tabId**，换标签 = 缓存丢失。
4. **抢同一个标签页**：`runOrders` 开头先补订单，与正在导航的页面打架，
   订单步骤卡死 4 分钟；桥 12 分钟重派又叠一轮。→ 跑任务时不再补订单；
   闹钟补订单有 running 就让路；桥重派前查队列/进度。

配套：
- `waitRecord(…, 12, …)` 只等 48 秒 → 45 轮（3 分钟），文件一好立刻返回。
- 待补核算只认**新落地**的订单表（`_orders_fresh`，mtime ≥ 待补登记时刻）。
  原来只要有订单表就算，拿别的月份算出 `GMV 0 / 净利 -93212` 的废报表。
- 同一区间 20 分钟内已排过，不再建导出任务：一上午反复重派把平台队列堵死，
  4 家店 20 多分钟一个文件都不出（正常店 90 秒出）。
