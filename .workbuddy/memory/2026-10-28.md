## v0.7.0 可分发程序与安装包（commit d49bc88）

### 用户新增需求
- 要能装到别的电脑直接用（含开机自启）
- 最接近原话：「程序做成 app 和安装包」
- 「和程序有关的文件都放同一个子文件夹」「源码和文档也放进去，全部打包走」

### 落地
- `release/净利助手/`（免安装，含 src/scripts/bridge/docs/README）
- `release/净利助手-免安装.zip`（9.6MB）
- `release/净利助手-安装包.exe`（18MB，PyInstaller onefile，内嵌 app.zip）
- 安装到 `%LOCALAPPDATA%\JingLiHelper`（ASCII 目录，避开编码坑），
  快捷方式/任务/注册表用中文显示名
- 构建：`python -m scripts.build_app`（--app-only 只重建 exe）

### 新增模块
- `src/paths.py` 统一路径（frozen 时 ROOT=exe 目录）；8 处 `__file__` 推算全部替换
- `src/app.py` 统一入口：menu/serve/run/install/uninstall/doctor/autostart
- `src/setup_core.py` 安装、卸载、schtasks 自启、快捷方式、注册表卸载项
- `installer/installer.py` 安装包
- `jingli.py` 项目根入口（PyInstaller 需要根目录在 sys.path，否则 `import src.*` 失败）

### 打包后暴露的三个坑（重要）
1. **GBK 控制台 + 特殊字符 = 崩溃**：`print("⚠…")` 抛 UnicodeEncodeError，
   整个进程退出。修法：stdout/stderr `reconfigure(errors="replace")`
2. **子进程输出被转码**：安装包捕获子进程 stdout 再打印，中文变问号。
   修法：不捕获，直接继承控制台
3. **frozen exe 忽略 PYTHONIOENCODING**：`--json` 里的中文变乱码，
   本地桥按 UTF-8 解析拿到替换符。修法：直接写 `sys.stdout.buffer` 的 UTF-8 字节

### 其它
- 构建脚本不再 `rmtree(release/X)`：批量删除触发安全策略，改逐文件覆盖
- `schtasks` 在本机沙箱被禁，开机自启无法在此验证，需用户在真机确认

### 仍未完成
- 扩展无法静默安装：装完必须在 chrome://extensions 加载 `<安装目录>\extension`
- 联盟佣金：导出接口只返 task_id 无下载地址；已加 `/transaction/detail_list/get`
  商品维度参数探测（module_type 104 + product_list_params 等 4 种形状），

## v0.10.0 订单口径四维拆开（commit f6b0f16）

### 用户指出的关键业务事实
「取消的订单，退货退款订单，0元样品订单他们都有发单费，商品成本费，
平台抽取的费用（除样品订单），所以加不加他们会很影响成本，影响净利结果」

**这是原设计的真错误**：以前 `include_cancelled` 一个开关控制整行，
关掉就把收入+成本+发单费一起关掉。但订单取消了，货采购了、发了、
发单费按单收了、平台抽成照收 —— 整行排除 = 成本被抹掉 = **净利虚高**。

### 数据结构：一行订单 → 四个独立口径
`income`（收入）/ `cost`（成本）/ `order_count`（订单数→发单费）/ `fee_base`（平台抽成基数）

按类别配（优先级：已取消 > 退货退款 > 0元 > 未付款 > 正常）：
- `cancelled`（115行）/ `refunded`（17行）/ `zero_amount`（47行）/ `unpaid` / `normal`
- 旧写法 `include_cancelled` 等仍兼容，映射成四项同开/同关

### 新增「计费基数」（关键设计）
`ProductMetrics.fee_base_gmv` / `fee_base_paid`。
平台佣金 `base=fee_base`、交易手续费 `base=fee_base_paid`。
**为什么必须新增**：取消单「收入不算但抽成照收」这个语义，
用同一个 `gmv` 字段表达不出来 —— 一关就全关了。
想按「退款时平台退佣」算，`fee_base: false` 即可。

### 踩坑：改配置毫无反应
`formula.load_config` 用白名单过滤 `order_filter`，只收 `include_xxx` 四个键，
嵌套的类别配置被 `if k in DEFAULTS[...]` 整个丢掉。
**症状极具误导性**：文件改了、进程重启了、结果一分没变，
第一反应会怀疑缓存或路径。改成整体接受 + 下游校验。

### 实测基准（马来西亚 demo-my，1386 行）
| 口径 | 成本 | 订单数 | 净利 |
| --- | ---: | ---: | ---: |
| 默认（取消/退货成本照算） | 6,576.37 | 796.00 | **2,235.49** |
| 取消/退货整行排除（旧） | 6,004.99 | 711.19 | 3,167.82 |

逐项对得上：成本 +571.38（=936.68 CNY×0.61）、发单费 +201.00（=84.81×2.37）、
平台佣金 +106.61（=1316.13×8.1%）、手续费 +53.35（=1411.46×3.78%）。

### 待用户确认
- **平台抽成对「取消/退货」是否退还**？现在默认照收（按用户原话）。
  若平台退款时退佣 → 把 `cancelled`/`refunded` 的 `fee_base` 设 false，净利 +160（106.61+53.35）。
- 退货的货若还能再卖，`cost` 可设 false。

## v0.11.0 参数表 + 配置界面（commit 3bd840c / 8fbc5c4）

### 用户的两次递进要求
1. 「参数不是有很多吗，有 gmv，佣金，各种平台收取的费用，发单费，订单服务费，
   商品成本，所有的计算参数都给一个开关选择要算哪些订单」
2. 「所有参与计算的参数包括 gmv 都有一个开关，所有类型的订单都在里面供我选择，
   开放，核心开放，供我自己选」
3. 「反正每个参数能让我自由选择算哪些类型的订单就行，要在 app 里方便配置修改」

### 最终模型：一张参数表
`config/formulas.json` 的 `params`，每行：
`{id, label, base, rate, kinds}` —— kinds 就是「算哪些订单类别」。

核心实现：**每行订单先按类别把原始量分开记**（ProductMetrics.by_kind：
gmv/buyer_paid/orders/items/cost/refund），参数表算值时按各自 kinds 合计。
所以同一个「订单数」，对发单费和对平台佣金可以是两个不同的数。
汇总成一个数就再也拆不开了 —— 这是整个设计的关键。

### 配置界面
`bridge/config_page.py` → `GET /config`。
桥本来就在跑、监听回环地址，加页面零成本，且能做「改完立刻试算」。
- 每个参数一行 + 5 个类别复选框
- 试算：当前 → 改后 → 变化（净利/成本/费用/GMV）
- 保存 / 新增参数 / 删除
- 数据按 mtime 缓存，反复试算不重复解析

### 修的三个 bug（都会让人以为"改了没反应"）
1. `compute_formulas` **从未被调用** —— formulas 段配了不生效，净利一直是硬编码属性
2. `rate` 不写时去取 `params.<id>`，导致 GMV 被当费率算成 **0**
3. 我写 config 时把 Python 的 `" + "` 拼进 JSON → 解析失败 → **静默退回默认值**

第 3 个尤其要记：配置解析失败必须报出来，不能静默 fallback，
否则表现是「改了文件毫无反应」，排查方向全错。

### 基准（马来西亚 demo-my，1386 行）
| 口径 | 净利 |
| --- | ---: |
| 默认 | 2,235.49 |
| 发单费只算正常+退货退款 | 2,510.41 |
| 再让平台佣金/手续费只算正常单 | 2,670.36 |
| 商品成本只算正常单 | 3,016.03 |
| 加订单服务费每单 2 元 | 891.10 |

### 待办
- 配置页现在是本地网页；若要独立窗口，套 pywebview（+15MB）即可，不用 PySide6
- 国家费率（rates.json）也应该做成同一套界面
- 广告/联盟数据文件仍未补回（被误删），需用户刷新扩展后触发一次取数

## v0.12.0 桌面窗口 + 界面重做（commit 待补）

1. 「app要有UI界面，和电脑应用程序一样」

### 技术选型：pywebview（不是 PySide6）
环境里 PySide6 6.12 和 WebView2 都有，但最后选 pywebview：
- PySide6 的 QtWebEngine 要多打 **150MB** 且带一整个 Chromium，启动慢

- 界面已经用网页做好了，重写成 Qt 原生控件等于重做一遍，
  而且参数表里一堆复选框，原生控件反而更啰嗦

窗口是系统原生窗口（有标题栏、任务栏图标、能最小化），
体感和别的电脑程序没区别。关窗口只关界面，桥继续在后台跑。

### 界面结构：左侧导航 + 5 个功能页
之前所有卡片堆一屏，太挤。重做为：
总览 / 开始核算 / 报表 / 参数配置 / 数据文件

设计规则（参考 Linear、Vercel、GitHub 后台）：
- 侧栏固定 216px，内容区 **限宽 880px 居中**，不拉满整屏
- 卡片间距 20px，页面上下留白 36px+
- 只用一种强调色（深绿 #0F6E56），其余靠灰阶分层
- 状态四格：数字放大 19px、说明缩到 12px 灰色

### 应用图标

PIL 画图，先 4 倍尺寸再缩小，边缘干净。多尺寸 16~256。
PyInstaller `--icon` + 发布目录带 `assets/`。

### 踩坑：timeout 管道会吃掉退出码
`timeout 10 ./jingli.exe 2>&1 | head -10; echo $?` 拿到的是 **head 的退出码**，
看起来像「窗口秒退」，实际窗口正常开着。

pywebview 的后端是运行时 import，PyInstaller 静态扫不到：
