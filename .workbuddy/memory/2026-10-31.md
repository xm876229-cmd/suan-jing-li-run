## v0.23.1（已打包同步，未上传 GitHub，git tag v0.23.1）

### 链接维度只认商品ID（src/calc.py）
- 删除「一行商品ID都没有 → 按商品名称归并」的兜底。标题会改，Chroma 101 条链接里 7 条出现过 2~3 个标题，按标题归并会把一条链接拆成多行，广告费（认商品ID）还挂不上。
- 查不到的行统一进「无ID」，异常页写清原因。
- 链接ID 的获取路径确认：订单表只有 SKU ID + Seller SKU → 查 `stores/<店>/商品SKU表/` 的 SKU ID→Product ID。七店实测命中率 98.1%~100%（CLI 已把该目录并入 load_from_dirs）。

### 菲律宾店日期解析（src/calc.py）
- 马来 `08/10/2026 23:58:53`（日/月/年）；菲律宾 `09/30/2026 11:35:45 PM`（月/日/年 + 12 小时制）。
- 旧代码不认 AM/PM 与月/日格式 → Created Time 全 None → `filter_by_date` 遇 None 直接保留 → **日期过滤整个失效**（要 10 月实际算了全部）。
- 新增 `date_order()`：按整批判断日在前/月在前（一整个月必有 >12 的日），`parse_dt(s, order)` 按该顺序解析。七店可解析率 100%。

### 广告 / 联盟佣金重复计入（src/loader.py）
- 这两张表是**区间汇总**（无日期列，一商品一行）。9/1~9/30 与 9/1~10/28 两份并存时，旧逻辑按行去重去不掉 → 相加 = 9 月算两遍。
- 新增 `_merge_aggregate()` + `table_range()`：读文件名/首行的区间；指定报表区间时挑「刚好盖住」的那份（最窄）；否则按包含关系丢掉被包住的；部分重叠保留并提示。
- Chroma 九月：广告 105,224→71,170、佣金 185k→126,825，净利 1.12%→20.67%。
- `RawData.ranges` 记录实际用的区间，`calc` 在区间与报表窗口不一致时写异常页。
