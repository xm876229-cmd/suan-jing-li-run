## 0.24.70 运行=重取 / 重算=用本机（2026-11-05 11:00）

- 口径定死：**运行（含计划任务）= 一律重新取数**，不复用当天同区间数据；
  **重算 = 一个请求都不发**，只用本机现有数据。UI 去掉「强制重新取数」勾选框，
  `/api/run-stores` 与 `_dispatch_rule` 都直接 force=True。
- `/run` 预检改用 `loader.orders_covering(dir, window, fresh_since)`：
  判据与核算一致（单份盖住 / 几份互不重叠拼整段）；fresh=true 时还要求
  **真正要用到的那几份**里有比本轮开始更新的（只看"最新文件 mtime"会被刚补回的 6 月文件骗过）。
- 不满足时：fresh → 登记待补并返回 `pending:true`；非 fresh（重算）→ `blocked:true`。
- 待补只在 `fresh` 成功时摘除。重算以前会顺手摘掉 → 新订单到了没人算。
- 扩展：`calcNow`/`registerPendingCalc` 带 `fresh:true` + `since`（runAllFast/Serial 开头记）；
  `harvestPendingOrders` 补回成功直接 POST /run（fresh + skip_if_done）自动出表。
- `skip_if_done`：同店同区间 3 分钟内算过就跳过（`_LAST_CALC`），避免待补线程与补回回调撞车。
- 待补里 `with_formula` 存 None（原来写死 False，补算的表会丢公式）。
- 删除已无引用的 `_orders_fresh`（并入 `orders_covering`）。
- 实测：沙盒桥 6 个场景 + 打包版 exe 复验（fresh→pending / 重算→ok 135.99）。
  真实数据 MYT-J3 10 月：旧表 25,481.32 → 新表 25,412.74（差 68.58 来自那份旧订单）。

## 0.24.72 「最新」= 导出时间（2026-11-05 11:20）

- 新增 `loader.export_time(path)`：身份证 srcmeta `at` → 文件名尾部 `YYYY-MM-DD-HH_MM` → mtime。
  起因：`cp -r`/解压备份/网盘同步会把 mtime 全改成"复制那一刻"，
  实测 10 份订单 mtime 全变同一秒，选出来的是 11-04 那份。
- 选择规则改成「区间对得上 + **整套里最旧那份**的导出时间最新」：
  单份盖住 / 几份拼起来 都算候选，按 min(导出时间) 比；并列再比窄、比份数。
  订单 prefer_fresh=True；广告/佣金仍窄优先（宽区间会把别的月份算进来）。
- 新增 `_cover_newest_first()`：从最新往回铺、盖满即停。
  `_union_cover` 的贪心会先抓整月表，导致"今天按周补导四周"永远轮不到（实测 A 案失败）。
- 实测 A/B：整月旧+周表新→选周表；整月新+周表旧→选整月；两份整月→新的；
  `cp -r` 后 mtime 全变 → 仍按文件名时间选中正确那份。
  三店回归与 0.24.71 逐位一致（MYT-V1 135.99 / MYT-J3 25,412.74 / PHT-M4 −20,500.03）。
- 教训：测试沙盒 `cp -r` 会破坏 mtime 语义；沙盒里也别带 `快照/`，
  `restore_inbox` 会把老表补回收件箱，干扰"用了哪份"的判断。

## 14:45 带公式版「链接毛利率」空白（0.24.76）

- 症状：报表页「导出带公式」下载的表，合计行 K 列「链接毛利率」空白，其它列正常；
  不带公式版有值（MYT-J3 50.3258%）。
- 根因：`_col_total()` 拼出 `IF($AC$2="不含样品",SUMIFS(明细!$AC:$AC,明细!$X:$X,0),
  SUMIFS(明细!$AC:$AC))` —— 第二个 SUMIFS **只有 1 个参数**。Excel/WPS 不报错、
  不给 #VALUE，直接留空白。只在「成本」列没勾选时走这条兜底，所以只有该店中招。
- 修：else 分支改 `SUM(明细!$col:$col)`；`audit_formulas` 新增第④条
  「SUMIFS 只有 1 个参数」（regex `SUMIFS\(([^,()]*)\)`）。
- 公式缓存改成按版本分目录：`报表/_公式缓存/v<ver>/<房间>/<店>/<报表>`（cli 写、bridge 读）。
  否则升级后不重算、只下载，会拷到上一版的坏缓存。顺手删了旧的 102MB 缓存。
- 验证：MYT-J3 公式版 K1 = SUM(...)，手算 (332,725.49−271,358.20×0.60908)/332,725.49
  = 50.3258%，与数值版一致；体检 0 问题。
