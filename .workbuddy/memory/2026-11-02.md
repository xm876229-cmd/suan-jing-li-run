## v0.24.1 第三段（计划任务 / 一步启动 / 界面重做）

### 计划任务（src/auto_run.py 重写）
- 一条计划 = 触发(每天/每周几/每月几号 + 时间) + 区间(周期 × 偏移 × 截到哪天)
- 周期：day / week / month / last7 / all；偏移 0=本期 1=上一期 N=N期前；
  截：end 整期 / today 到今天 / day 第 N 天
- `build_range(rule, when)` 返回全套字段（startDate/to/endDateExclusive/startMs/endMs/tzOffset）
- `last_due` / `next_due` / `fires_on`；`quick_rule(kind)` 把「上月/近7天」这类快捷区间转成规则
- 状态文件 `数据/schedule_state.json`：`mark` = 处理水位（判漏跑），`last` = 真跑过的时刻（界面显示）
- 桥 `_schedule_runner` 每 20 秒巡检，容差 600 秒；超时记 missed，界面可一键补跑（按当时该跑的时刻算区间）

## v0.24.5（13:35 打包，13:39 发布）

用户报：「release/净利助手/数据 里怎么还是英文文件夹」

### 真因
改名只发生在 `import paths` 那一刻，且只作用于**当前数据根**。
release / 安装版目录从没被新版程序打开过 → 一直是英文。

### 做法
- `paths.migrate_data_dirs(root)`：改名 + 两边都在时 `_merge_into` 合并；只改名不删
- `scripts/migrate_dirs.py`（`--check` 只看不改）；`_load_paths()` 用 JINGLI_HOME 指向临时目录，
  避免 "import 就改了"导致检查永远看不出问题
- `sync_all` 每个版本同步时顺带迁；`build_app` 打包前迁
- 本机实测：免安装 8 处、安装 6 处、项目 2 处（含 `店铺/未识别店铺/inbox`）

### 顺带挖出的三个坑（都不报错、静默坏）
1. **包内带了 `数据目录.txt`**（内容 `..\..`）。解压到桌面 → 数据根 = 桌面的上一级，
   数据/配置/报表散到程序目录外。已加进 `_skip_in_pack`
2. **`_skip_in_pack` 只认英文目录名**。改成中文后规则全失效 →
   45 个店铺文件（订单+快照）会进包。改成 `_PRIVATE_DATA_DIRS` 中英都收录；
   `verify_release.check_portable` 增加硬检查：zip 里有店铺数据/数据目录.txt 直接拒发
3. **`setup_core` 拷种子成本表用英文路径** → 全新安装后成本表空，
   第一次核算成本按 0、净利虚高且无提示

### 同类失效（写死英文目录，全是空跑）
`sync_all.COST_SRC`、`build_app` 的 `_paths.DATA/"costs"`、补种子循环 `("costs","mapping")`

## v0.24.6 全面体检（13:52 打包，13:54 发布）

用户要求：完整检查程序，找会导致「异常不可用」和「不常规操作让程序死机」的隐患。

### 体检方法（可复用）
1. `python -m pyflakes` 全项目 → 只看 F821（未定义名）。43 模块全导入。
2. 起沙箱桥（`JINGLI_HOME=.tmp_fuzz` + 独立端口），
   30 个 POST 端点 × 10 种畸形 body（`{}`/`{bad`/空/`[]`/`"str"`/`null`/
   错误类型/深嵌套/200KB 值/负数）
3. 原始 socket 发畸形 `Content-Length`（负数、乱写、声称 100MB 不发）
4. 连点压测：30 线程同时 `/api/run-stores` 同一店
5. 并发写配置：30 线程 `schedules/save`、40 线程 `settings`
6. 12 个页面 headless Chrome 遍历（正常 + 全部接口 reject），抓 `window.onerror`
7. 9 种坏表格喂 `read_table`（UTF-16/BE/BOM/半截引号/300KB 字段/NUL/二进制/空/仅表头）
8. 打包版再跑一遍（防 PyInstaller 排除模块导致行为不同）

### 修掉的问题（都实测复现过）
- **请求层 67 条异常 → 0**：负数/超大 Content-Length 会让线程永久卡住；
  非 dict body 让 7 个接口断连接（前端只看到 Failed to fetch）
  → `Handler._read_payload()`（长度校验/8MB/上传 200MB/必须 dict）
  + `do_GET`/`do_POST` 外层兜底 + `_where()` 记行号 + `timeout=30`
- **连点 30 次 = 30 个任务 → 1 个**：`_enqueue` 同店同 task 新顶旧
- **settings 被杂字段写脏**：`save()` 加 DEFAULTS 白名单 + 类型校验
- **stores.json 缺失 → 店铺列表空 + 报错**：改 safeio + 不提前 return
- **4 处硬编码 `inbox`**（店铺文件数/config_page/costs_api/import_mapping）：
  → `paths.store_inbox()`；`inbox_count` 改递归
- **`_STORE_NAMES` 永久缓存**：改按 mtime 失效
- **`_norm_fields` 对非 dict 抛异常**：一条坏规则让计划页全 500
- **UTF-16 读成空表 / BOM 残留在表头**：按 BOM 判断 + `utf-16` 解码 + 剥 BOM
- **csv 128KB 字段上限**：放宽到 10MB；编码全失败改为明确报错
- **日期日月序判错整月错位**：`date_order` 加「无证据」第三态，
  `filter_by_date` 用区间命中数定
- **`master.new.csv` 永久滞留**：核算前 `_promote_pending()`
- 前端：`/api/live` 防重入；上传限 200MB
