# 算净利润（suan-jing-li-run）

TikTok Shop 跨境电商（马来西亚 / 菲律宾 / 泰国）**按商品（链接）核算净利润**的本地工具。

把原来「人工导出 → 手工填四列 → Excel 拉公式」的流程，换成「取数 → 核算 → 出报表」一条流水线，
三种运行方式（命令行 / 双击 / 定时任务）共用同一套逻辑。

## 一、快速开始

### 方式一：命令行（最灵活）

```bash
# 读主工作簿里的原始表，算全量
python -m src.cli --workbook "V1-净利  -15.xlsx" --country 马来西亚

# 指定区间（任意起止，哪怕只算两天）
python -m src.cli --workbook "V1-净利  -15.xlsx" --from 2026-10-01 --to 2026-10-15

# 读导出目录（推荐：手工导出后放到一个文件夹即可）
python -m src.cli --dir data/exports/demo-my/20261001-20261015 --costs "V1-净利  -15.xlsx"

# 分别指定四个文件（更精确）
python -m src.cli --orders 订单.xlsx --ads 广告.xlsx \
                  --commissions 联盟佣金.xlsx --mapping 找id用的.xlsx \
                  --costs "V1-净利  -15.xlsx" --country 马来西亚

# 按店铺清单跑（店铺配置见 config/stores.json）
python -m src.cli --workbook "V1-净利  -15.xlsx" --store demo-my
```

### 选店铺就是选国家

`config/stores.json` 里每家店写上国家，之后**只管选店**，国家、费率、报表命名都跟着它走：

```json
{
  "stores": [
    { "id": "demo-my", "name": "马来西亚一店", "country": "马来西亚", "browser_id": "1510442" }
  ]
}
```

- 菜单里选店 → 国家自动带出，不用手填两处
- 扩展面板上也是下拉选店，配置改了刷新面板就生效（走本地桥的 `/stores` 接口，不用重装扩展）
- 核算时只传 `--store`，国家由配置统一决定，避免面板填的和配置里的打架

### 解析层是按表头名识别，不认列号也不认文件名

平台导出模板会变、人工会在前面插列、默认文件名还全是英文，所以：

- **表的类型靠表头特征判断**：有 `Order ID` 就是订单表，有 `商品 ID`+`成本` 是广告表，
  有 `商品 ID`+`预计佣金` 是联盟佣金表，有 `SKU ID`+`Product ID` 是商品映射表。
  文件名随便叫（`全部 笔订单-2026-10-27-16_59.csv`、`creative data for product campaigns ...`）都能认。
- 表头在第几行自动找（前 8 行里挑最像的），所以「第 1 行标题 + 第 3 行表头」也能处理
- 中英文表头都认（`Sku Subtotal Before Discount`、`商品 ID`、`预计佣金`…）
- 第 2 行的英文说明行自动跳过
- `RM2,678.75`、带制表符的 CSV 值都能正确解析
- 广告按「货币」列自动换算（USD → 本地），**不会乘两次汇率**
- `Order Amount` 是订单级金额，按订单内行数平分（与旧表口径一致）

> **GMV 口径提示**：报表沿用旧表的「折扣前小计 − 卖家折扣」，而平台后台统计的 GMV 是买家实付口径。
> 同一期间两者会差 1.8 倍左右（例：2026-10-01~10-15，本引擎 13,074.78，平台统计 14,770.66，买家实付 15,219.88）。
> 这个口径待定，切换只需要改 `calc.py` 里 `OrderLine.gmv` 一处。


### 成本表：主表 + 变更流水

成本只在新增商品时更新，所以不做成"每次读最新文件"，而是维护一张主表：

```bash
# 把新导的成本表丢进 data/costs/，执行一次
python -m scripts.import_costs "data/costs/成本表.xlsx"
```

- `data/costs/master.csv`：主成本表，程序算账只认这张
- `data/costs/history.jsonl`：变更流水，涨价/降价/新增都有记录（旧价 → 新价 + 时间）
- 老编码不会被新表"冲掉"，价格没变就不动
- 第一次没有主表时，程序会自动把目录里最新的表导入建表
- 成本数据目录已 gitignore，不会上传


### SKU→商品 映射：同样是主表 + 变更流水

映射**不能**当成"一个月才变一次"的静态表。链接一编辑，SKU 归属就可能变，频率高时一天一次。
所以不做缓存，每次取数都拉全量，并且增量合并进主表：

```bash
python -m scripts.import_mapping                    # 合并 _inbox 里所有 sku_list_*.json
```

- `data/mapping/master.csv`：累积主表，新 SKU 追加、老 SKU 永远保留
- `data/mapping/history.jsonl`：新增 / **改绑**（SKU 换到另一个商品）都有流水
- 主表与导出目录里的映射表**合并使用**（主表优先），任一方不完整都不会算错
- `src/cli.py` 发现更新的 `sku_list_*.json` 会自动合并，平时不用手动跑

> 为什么必须累积：只用最新那份时，链接改过之后老 SKU 会消失，历史订单里那些行就找不到商品ID，
> 整片归进「未识别商品」——报表看起来正常，实际少算了那个商品的全部净利。

### 已预置的国家与汇率

东南亚 + 欧美共 12 个国家已配好，不用改代码就能用：
马来西亚、菲律宾、泰国、越南、新加坡、印尼、美国、英国、德国、法国、意大利、西班牙。

汇率三档可切（`config/rates.json` 的 `fx` 段）：

```json
"fx": {
  "mode": "auto",                  // auto = 联网抓实时；manual = 只用固定值
  "provider": "open.er-api.com",
  "ttl_hours": 12,                // 缓存 12 小时，避免同一天跑出两个数
  "manual": {}                    // 只固定某一个国家：{"泰国": {"cny_to_local": 4.91, "usd_to_local": 33.0}}
}
```

- `auto`（默认）：优先抓实时汇率；断网或接口挂了自动退回配置里的兜底值，**不会让整次核算失败**
- `manual`：完全不联网，只用配置里写的固定值
- 只想临时换一种：`--fx auto` / `--fx manual`
- 这次实际用的汇率来源会写进报表「口径与参数快照」页，事后能查清

> 除了马来西亚、菲律宾，其余国家的费率是**占位值**（`rates_verified: false`），
> 报表里会明确标出来。第一次跑某个新国家前，请按店铺后台的实际费率改 `config/rates.json`。

### 新增国家不用改代码

在 `config/rates.json` 的 `countries` 下加一段就行，键名与 `--country` 一致：

```json
"美国": {
  "cny_to_local": 0.14, "usd_to_local": 1.0,
  "dispatch_fee_cny": 3.0, "dispatch_fee_local": 0.42,
  "platform_commission": 0.06, "tx_fee": 0.029,
  "cashback": 0.0, "super_coupon": 0.0, "growth_fee": 0.0, "logistics": 0.0
}
```

- `cny_to_local` = 1 人民币兑多少该国货币；`usd_to_local` = 1 美金兑多少
- 费率按小数填（8.1% 写 `0.081`），去该国卖家后台「费用说明 / 费率」页抄
- 拿不准的先填 0，报表「口径」页会把每项取值列出来，方便回头核对
- 国家不存在时程序会直接报错并列出已配置的国家，不会静默算错

## 三、核算口径

口径全部由 `config/formulas.json` 驱动，**不用改代码**，改完即时生效。

```
GMV       = Σ(折扣前小计) − Σ(卖家折扣)        取消/退货单按「订单口径」决定
成本       = 成本表单价 × 数量 × 人民币→本地汇率
发单费     = 订单数 × 发单费(本地)              按单收，不按金额
平台佣金   = 平台抽成计费基数 × 佣金率          基数含取消/退货，不含 0 元样品单
交易手续费 = 平台抽成计费基数(实付) × 费率
奖金返现 / 超级优惠券 / 商家成长 / 物流 = GMV × 各自费率
达人佣金   = 联盟报表按商品ID汇总（预估佣金）
广告花费   = 广告报表按商品ID汇总 × 美金→本地汇率
净利(本地) = GMV − 成本 − 各项费用合计
净利(人民币) = 净利(本地) ÷ 人民币汇率
```

### 订单口径：收入和成本必须分开算

这是最容易算错的地方。**取消单、退货单、0 元样品单的收入是 0，但成本是真实发生的**——
货采购了、发出了，发单费按订单数照收，平台抽成也照收（样品单除外）。
以前的实现是「一个开关控制整行」，关掉就把成本也抹掉了，**净利会虚高**。

现在每类订单四个开关独立控制（`config/formulas.json` 的 `order_filter`）：

| 开关 | 管什么 |
| --- | --- |
| `income` | 收入：GMV 与买家实付 |
| `cost` | 商品成本（含件数） |
| `order_count` | 订单数 → 发单费等按单计费的基数 |
| `fee_base` | 平台抽成计费基数 → 平台佣金、交易手续费等按比例的项 |

默认口径：

| 订单类别 | 收入 | 成本 | 发单费 | 平台抽成 |
| --- | :---: | :---: | :---: | :---: |
| 已取消 | ✗ | ✓ | ✓ | ✓ |
| 退货退款 | ✗ | ✓ | ✓ | ✓ |
| 0 元样品单 | ✓（本就是 0） | ✓ | ✓ | ✗ |
| 未付款 | ✗ | ✗ | ✗ | ✗ |
| 正常 | ✓ | ✓ | ✓ | ✓ |

改其中一项，只写那一项就行（其余沿用默认）：

```json
"order_filter": {
  "cancelled": { "fee_base": false }     // 如果平台在退款时把佣金退了
}
```

> 一行订单只归一类，优先级：已取消 > 退货退款 > 0 元样品单 > 未付款 > 正常。
> `refund_keywords` 可配「什么字样算退货」，默认 `["return","refund"]`。

**报表「口径」页会把本次实际生效的每类订单行数与计入项列出来**，事后对账不用猜。

### 几个关键约定

- **订单数与买家实付按订单内行数平分**。一个订单的分配数合计为 1，这是原表的口径，
  引擎已 100% 复刻。想改成「按行 GMV 占比」，把 `config/rates.json` 里
  `allocation_paid` 改成 `proportional`（更准，但与旧表会有细微差异）。
- **成本三级解析**：成本表精确命中 → 多件装（`-2Pcs` 按基座价×件数）→ 组合装（`+` 拆开相加）。
  都查不到就记进异常页，按 0 计，**绝不猜**。
- **商品ID 三级定位**：平台 SKU ID（唯一）→ 卖家 SKU → 多件装/组合装拆解后的基座 SKU。
- **超级优惠券默认按 0 计**（沿用原表 `×0` 的开关），在 `rates.json` 里可打开。

## 四、口径校验

`python -m scripts.validate` 会把引擎结果与主工作簿「净利润」表逐项比对：

| 校验项 | 结果 |
| --- | --- |
| 商品ID 映射 | 1884 / 1887 = **99.84%** |
| 订单数分摊 | **100%**（0 偏差） |
| 买家实付分摊 | **100%**（0 偏差） |
| 成本 | 1893 / 1896 一致 |
| 合计 GMV | 17352.29 对 17352.29（**一致**） |
| 合计净利 | 267.08 对 302.22，差 −35.14 |

那 −35.14 的来源已定位：`MY-J12-5PCS` 三行，原表成本填的是 0，引擎按「5 × 3.84」推出 19.2，
换算后正好 35.14。**是原表漏填，不是算错。**

## 五、取数自动化（进行中）

`endpoints.json` 就是后续自动取数的目标清单——**先看清真实接口，再写自动化，不靠猜页面结构。**



### 一键运行（推荐用法）

扩展面板上一个按钮就跑完全流程，不用命令行：

```
立即运行：取数 + 算净利
  ↓
订单 / 商品SKU / 联盟佣金 / 广告（已完成任务）
  ↓
POST /run → 本地 Python 核算 → 出 Excel
  ↓
面板直接显示净利、人民币、净利率、商品数、异常数
```

面板上还有：

| 按钮 | 作用 |
| --- | --- |
| 立即运行：取数 + 算净利 | 全流程，随时可点，不等定时 |
| 只算净利（不取数） | 用 `_inbox` 里现有文件重算，改费率/成本后立刻验证 |
| 四个分项按钮 | 单独补某一种数据（也是取完自动核算） |

日期区间、核算国家都在面板上选，面板关闭重开会记住上次的选择。

**定时**：勾选「每周 X 点」或「每月 N 日」，到点自动执行同一套流程
（扩展内 `chrome.alarms` 触发，不需要打开面板）。前提是浏览器和店铺环境开着。

### 全自动取数：五类数据的现状

扩展现已支持**自动执行导出任务**，不用再手工点按钮：

1. 先手工打开一次店铺后台的任意页面（让扩展学到该店铺的公共参数）
2. 点扩展图标 → 选店铺与起止日期 → 点「立即运行」
3. 扩展依次做：创建导出任务 → 轮询导出记录 → 取签名下载地址 → 下载 → 回传到 `data/exports/_inbox/`

| 数据 | 接口 | 状态 |
| --- | --- | --- |
| 订单 | `/api/fulfillment/order/export` → `export_record/get` → `download` | ✅ 全自动 |
| 商品管理 SKU（映射**主来源**） | `/api/v1/product/stock/sku/list`（翻页取全量在售） | ✅ 全自动 |
| 链接资料（映射**补充**） | `/api/v2/insights/seller/ttp/product/sku/list/export` | ✅ 全自动 |
| 联盟佣金 | `/api/v1/oec/affiliate/compass/transaction/detail_list/get` | ✅ 全自动 |
| 广告 | `/oec_ads/shopping/v1/oec/stat/post_product_list_v2` | ✅ 全自动 |

> 广告这一条原先卡了很久：导出接口的 list 只返回 task_id 没有下载地址，
> 一直以为必须先在页面上点「导出」才行。
> 后来抓到页面自己发的请求才发现——**同一个接口不带 `action` 参数就直接返回数据**
> （`data.table_v2`），压根不用走导出流程。
> 抓包方法见下方「抓包模式」，调接口的技能比猜参数可靠得多。

回传的文件按类型分开落盘：

- 订单 / 广告 / 联盟佣金 → `data/exports/_inbox/`（核算引擎直接消费）
- 商品管理 SKU / 链接资料 → `data/mapping/`（只进映射主表，不参与订单核算）

用 `--dir` 指向 inbox 目录即可出报表：

```bash
python -m src.cli --dir data/exports/_inbox --costs "V1-净利  -15.xlsx" --country 马来西亚
```

**为什么必须"在页面上下文里发请求"**：接口依赖 Cookie 和风控参数（`fp`、`X-Tts-Oec-Bsid`），
这些只存在于对应域名的页面里。扩展从真实请求里学一份最新参数再重放，不伪造、不破解。

各数据源的时间参数格式：

| 数据源 | 参数格式 |
| --- | --- |
| 订单 | `time_order_created: ["1590000000000","1590000000000"]`（毫秒） |
| 商品 SKU | `time_descriptor: {"start":"2026-10-01","end":"2026-10-16"}`（日期串，end 开区间） |
| 联盟佣金 | `start_time / end_time`（秒）+ `time_context: "101"`（**少了这个接口不认**） |
| 广告 | 只有查询 `download_task/query`，创建环节待抓 |

### 抓包模式（查新接口时用）

程序自动调接口，是建立在「知道真实参数」的前提上的。平台改版或要接新数据时，
用扩展抓一次真实流量，比猜参数靠谱得多：

1. 在战斧里切到要抓的页面
2. 点扩展面板上的「**① 先点我，再去广告页点一次「导出」**」
   ——监听是全局的，切页不影响；日志会列出各页面上有哪些「导出」按钮
3. 在页面上做你要抓的动作
4. 抓到的请求实时落到 `data/capture/ads_export.jsonl`

> **踩过的坑**：抓包记录只记 URL 不记请求体，等于白抓。
> `chrome.webRequest` 的 extraInfoSpec 里必须带 `"requestBody"`，
> 否则 `details.requestBody` 一直是 undefined。
> 响应样本也截得太狠（原来 6000 字符，很多返回正好被截断，字段看不全只能靠猜），
> 现在放宽到 30000。
