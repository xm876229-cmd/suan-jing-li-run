# 算净利润（suan-jing-li-run）

TikTok Shop 跨境电商（马来西亚 / 菲律宾 / 泰国）**按商品（链接）核算净利润**的本地工具。

把原来「人工导出 → 手工填四列 → Excel 拉公式」的流程，换成「取数 → 核算 → 出报表」一条流水线，
三种运行方式（命令行 / 双击 / 定时任务）共用同一套逻辑。

## 一、快速开始

### 方式一：命令行（最灵活）

```bash
# 读主工作簿里的原始表，算全量
python -m src.cli --workbook "V1-净利  -15.xlsx" --country 马来西亚

# 指定区间（任意起止，哪怕只算两天）
python -m src.cli --workbook "V1-净利  -15.xlsx" --from 2026-10-01 --to 2026-10-15

# 读导出目录（推荐：手工导出后放到一个文件夹即可）
python -m src.cli --dir data/exports/demo-my/20261001-20261015 --costs "V1-净利  -15.xlsx"

# 分别指定四个文件（更精确）
python -m src.cli --orders 订单.xlsx --ads 广告.xlsx \
                  --commissions 联盟佣金.xlsx --mapping 找id用的.xlsx \
                  --costs "V1-净利  -15.xlsx" --country 马来西亚

# 按店铺清单跑（店铺配置见 config/stores.json）
python -m src.cli --workbook "V1-净利  -15.xlsx" --store demo-my
```

### 选店铺就是选国家

`config/stores.json` 里每家店写上国家，之后**只管选店**，国家、费率、报表命名都跟着它走：

```json
{
  "stores": [
    { "id": "demo-my", "name": "马来西亚一店", "country": "马来西亚", "browser_id": "1510442" }
  ]
}
```

- 菜单里选店 → 国家自动带出，不用手填两处
- 扩展面板上也是下拉选店，配置改了刷新面板就生效（走本地桥的 `/stores` 接口，不用重装扩展）
- 核算时只传 `--store`，国家由配置统一决定，避免面板填的和配置里的打架

### 解析层是按表头名识别，不认列号也不认文件名

平台导出模板会变、人工会在前面插列、默认文件名还全是英文，所以：

- **表的类型靠表头特征判断**：有 `Order ID` 就是订单表，有 `商品 ID`+`成本` 是广告表，
  有 `商品 ID`+`预计佣金` 是联盟佣金表，有 `SKU ID`+`Product ID` 是商品映射表。
  文件名随便叫（`全部 笔订单-2026-10-27-16_59.csv`、`creative data for product campaigns ...`）都能认。
- 表头在第几行自动找（前 8 行里挑最像的），所以「第 1 行标题 + 第 3 行表头」也能处理
- 中英文表头都认（`Sku Subtotal Before Discount`、`商品 ID`、`预计佣金`…）
- 第 2 行的英文说明行自动跳过
- `RM2,678.75`、带制表符的 CSV 值都能正确解析
- 广告按「货币」列自动换算（USD → 本地），**不会乘两次汇率**
- `Order Amount` 是订单级金额，按订单内行数平分（与旧表口径一致）

> **GMV 口径提示**：报表沿用旧表的「折扣前小计 − 卖家折扣」，而平台后台统计的 GMV 是买家实付口径。
> 同一期间两者会差 1.8 倍左右（例：2026-10-01~10-15，本引擎 13,074.78，平台统计 14,770.66，买家实付 15,219.88）。
> 这个口径待定，切换只需要改 `calc.py` 里 `OrderLine.gmv` 一处。


### 成本表：主表 + 变更流水

成本只在新增商品时更新，所以不做成"每次读最新文件"，而是维护一张主表：

```bash
# 把新导的成本表丢进 data/costs/，执行一次
python -m scripts.import_costs "data/costs/成本表.xlsx"
```

- `data/costs/master.csv`：主成本表，程序算账只认这张
- `data/costs/history.jsonl`：变更流水，涨价/降价/新增都有记录（旧价 → 新价 + 时间）
- 老编码不会被新表"冲掉"，价格没变就不动
- 第一次没有主表时，程序会自动把目录里最新的表导入建表
- 成本数据目录已 gitignore，不会上传


### SKU→商品 映射：同样是主表 + 变更流水

映射**不能**当成"一个月才变一次"的静态表。链接一编辑，SKU 归属就可能变，频率高时一天一次。
所以不做缓存，每次取数都拉全量，并且增量合并进主表：

```bash
python -m scripts.import_mapping                    # 合并 _inbox 里所有 sku_list_*.json
```

- `data/mapping/master.csv`：累积主表，新 SKU 追加、老 SKU 永远保留
- `data/mapping/history.jsonl`：新增 / **改绑**（SKU 换到另一个商品）都有流水
- 主表与导出目录里的映射表**合并使用**（主表优先），任一方不完整都不会算错
- `src/cli.py` 发现更新的 `sku_list_*.json` 会自动合并，平时不用手动跑

> 为什么必须累积：只用最新那份时，链接改过之后老 SKU 会消失，历史订单里那些行就找不到商品ID，
> 整片归进「未识别商品」——报表看起来正常，实际少算了那个商品的全部净利。

### 已预置的国家与汇率

东南亚 + 欧美共 12 个国家已配好，不用改代码就能用：
马来西亚、菲律宾、泰国、越南、新加坡、印尼、美国、英国、德国、法国、意大利、西班牙。

汇率三档可切（`config/rates.json` 的 `fx` 段）：

```json
"fx": {
  "mode": "auto",                  // auto = 联网抓实时；manual = 只用固定值
  "provider": "open.er-api.com",
  "ttl_hours": 12,                // 缓存 12 小时，避免同一天跑出两个数
  "manual": {}                    // 只固定某一个国家：{"泰国": {"cny_to_local": 4.91, "usd_to_local": 33.0}}
}
```

- `auto`（默认）：优先抓实时汇率；断网或接口挂了自动退回配置里的兜底值，**不会让整次核算失败**
- `manual`：完全不联网，只用配置里写的固定值
- 只想临时换一种：`--fx auto` / `--fx manual`
- 这次实际用的汇率来源会写进报表「口径与参数快照」页，事后能查清

> 除了马来西亚、菲律宾，其余国家的费率是**占位值**（`rates_verified: false`），
> 报表里会明确标出来。第一次跑某个新国家前，请按店铺后台的实际费率改 `config/rates.json`。

### 新增国家不用改代码

在 `config/rates.json` 的 `countries` 下加一段就行，键名与 `--country` 一致：

```json
"美国": {
  "cny_to_local": 0.14, "usd_to_local": 1.0,
  "dispatch_fee_cny": 3.0, "dispatch_fee_local": 0.42,
  "platform_commission": 0.06, "tx_fee": 0.029,
  "cashback": 0.0, "super_coupon": 0.0, "growth_fee": 0.0, "logistics": 0.0
}
```

- `cny_to_local` = 1 人民币兑多少该国货币；`usd_to_local` = 1 美金兑多少
- 费率按小数填（8.1% 写 `0.081`），去该国卖家后台「费用说明 / 费率」页抄
- 拿不准的先填 0，报表「口径」页会把每项取值列出来，方便回头核对
- 国家不存在时程序会直接报错并列出已配置的国家，不会静默算错

### 双击没反应 / 报「找不到 python」

Windows 自带的 `WindowsApps\python.exe` 是个**商店占位程序**，双击时什么都不做。
所有批处理都通过 `scripts\_python.bat` 自动找一个真正能用的解释器，搜索顺序：

1. 环境变量 `PYTHON_EXE`
2. PATH 里的 `python`（跳过 `WindowsApps` 占位）
3. `py` 启动器
4. `%LOCALAPPDATA%\Programs\Python\Python3xx`、`C:\Python3xx`、`%ProgramFiles%\Python3xx`
5. WorkBuddy 自带的 Python（本机当前走这条）

都没有才会报错。要固定用某个解释器，设一个环境变量即可：

```powershell
setx PYTHON_EXE "C:\Path\To\python.exe"
```

> 批处理内容全部为纯 ASCII，避免中文在 cmd 里因编码不同而乱码。

## 三、核算口径

口径全部由 `config/formulas.json` 驱动，**不用改代码**，改完即时生效。

```
净利     = gmv − 商品成本 − 发单费 − 平台佣金 − 交易手续费
           − 奖金返现 − 广告花费 − 达人佣金 − 订单服务费
净利率   = 净利 ÷ gmv
gmv      = Σ(折扣前小计) − Σ(卖家折扣)
商品成本 = Σ(购买数量 × 成本表单价) × 人民币汇率
发单费   = 链接订单数 × 一单发单费(人民币) × 人民币汇率
订单服务费 = 链接订单数 × 每单固定费用(本地货币)
平台佣金 = gmv × 佣金率
交易手续费 = 买家实付 × 费率        （不是上面那个 gmv，是买家实际付的钱）
广告花费 = 广告表该链接花费(美金) × 美金汇率
           （本期没出单但有广告费的链接也算，单独成行；N/A、NULL 归「无ID」）
达人佣金 = 联盟表该链接的预估佣金
奖金返现 = gmv × 4.86%          （模板里就有这一项，默认算）
```

> 「其他费用」不是固定的名字：要加新费用，去「费率」页加一项费率，
> 再在计算参数里加一条 `gmv * params.新字段`，最后把它写进净利公式。

### 公式里直接写订单表的列标题

**不再有单独的「列映射」页面**。公式里写标题就是映射：

```
[折扣前小计|SKU Subtotal Before Discount] - [卖家折扣|SKU Seller Discount]
```

- 方括号里一个标题，或者多个候选用 `|` 分开——第一个在订单表里找不到就试第二个，直到找到
- 也可以裸写：`折扣前小计 - 卖家折扣`（只要这个标题在订单表里存在）
- 界面里「公式里能写什么」会把**当前订单表的真实表头**列出来，点一下插到光标处
- 换国家、换语言、平台改列名：改公式里的标题就行，代码一个字不动

除了标题，公式里还能写这些「算好的量」：

| 变量 | 含义 |
| --- | --- |
| `gmv` | 按这一项勾选的订单类别，算 Σ折扣前小计 − Σ卖家折扣 |
| `paid` | 买家实付合计 |
| `qty` / `orders` | 件数 / 订单数（订单内多条链接按 SKU 行数分摊） |
| `cost_cny` / `cost` | 商品成本（人民币 / 当地货币） |
| `cost_unit` | 平均成本单价（人民币） |
| `refund` | 退款金额 |
| `commission` / `ads` | 达人佣金 / 广告花费（整期，来自数据源，不看订单类别） |
| `params.xxx` | 这个国家的费率，在「费率」页维护 |
| `param.xxx` | 参数表里另一项算出来的值（如 `param.gmv`） |

### 三个模块，各管一件事

| 模块 | 管什么 | 存在哪 |
| --- | --- | --- |
| **成本表** | 商品编码 → 成本单价（人民币）；哪一列是编码/成本也能配 | `data/costs/master.csv` + `formulas.json` 的 `cost_fields` |
| **费率** | 每个国家的佣金率、手续费率、发单费、订单服务费…… | `config/rates.json` |
| **计算参数** | 每一项怎么写公式、算哪些订单；订单表识别用哪几列 | `config/formulas.json` |

三者都按**国家**分开：店铺属于哪个国家，就套用那个国家的一套。
没单独设过的国家，用「通用」那套。

### 计算参数：每一行就是一条公式

当前默认（**每项都能随时改**）：

| 参数 | 公式 | 正常 | 已取消 | 退货退款 | 0元样品 |
| --- | --- | :---: | :---: | :---: | :---: |
| GMV（收入） | `[折扣前小计\|SKU Subtotal Before Discount] - [卖家折扣\|SKU Seller Discount]` | ✓ | | | ✓ |
| 商品成本 | `cost_cny * params.cny_to_local` | ✓ | | | ✓ |
| 发单费 | `orders * params.dispatch_fee_cny * params.cny_to_local` | ✓ | | ✓ | ✓ |
| 订单服务费 | `orders * params.order_service` | ✓ | | ✓ | |
| 平台佣金 | `gmv * params.platform_commission` | ✓ | | | ✓ |
| 交易手续费 | `paid * params.tx_fee` | ✓ | | | |
| 奖金返现 | `gmv * params.cashback` | ✓ | | | ✓ |
| 广告花费 | `ads` | 不看订单类别（来自广告表） | | | |
| 达人佣金 | `commission` | 不看订单类别（来自联盟表） | | | |

- 「0 元样品单」的 GMV 和买家实付本来就是 0，所以勾不勾对 GMV、交易手续费这些按金额算的项没有影响；
  但它有货、有发单费，所以**成本、发单费照样算**
- **订单数、件数**这两行是报表上的显示列，也各有勾选、单独控制：
  勾了「0元样品」订单数就含样品单，取消就只算正常 + 退货。发单费、服务费里的 `orders`
  按各自那一行的勾选算，所以「订单数 973 单、服务费按 927 单」这种组合是允许的
- **想一次性全去掉样品单，用参数表下面的总开关「去除 0 元样品订单」**：
  打开后所有勾了样品的项一起剔掉（成本、发单费、订单数、件数都变），
  算出来是纯正常订单（含退货）的净利；关掉后各参数恢复按自己的勾选算
- 每项自己勾**算哪些订单类别**（如「剔除取消的订单」就把已取消那格取消）
- 改完点「试算」，立刻看到 GMV／成本／费用／净利的「当前 → 改后 → 变化」
- 净利公式在「净利怎么算」里，默认把上面每一项减掉；**新增参数后记得把它加进这一行**

### 一次算出两套净利（含样品 / 去样品）

核算时内部会跑两遍——一遍按「含 0 元样品单」，一遍按「剔除后」，
所以报表里**两套数都在**，不用再「切开关 → 重算 → 记数字 → 切回来」：

| 位置 | 内容 |
| --- | --- |
| 汇总页末尾两列 | `净利（去除 0 元样品单）` 或 `净利（含 0 元样品单）`、`样品差额` |
| 「样品对比」页 | 逐条链接列出 GMV / 商品成本 / 发单费 / 两套净利 / 样品影响 |

主口径（净利(本地货币) 那列）跟着你在参数页的开关走，对比列永远是另一套。

### 预设：口径一键切换，按店铺分设

计算参数和费率调一次很费劲，调完还想着留着、随时切回来——所以有了预设。

**两级作用域**

- **全局预设**：所有店铺通用
- **店铺预设**：只对某一家店生效，优先级高于全局

**一份预设能装什么**

计算参数表（每项勾了哪些订单类型）、净利公式、订单表识别清单、
成本表列标题、「去除 0 元样品订单」总开关，以及（勾选后）各国费率。

**怎么用**

「计算参数」页和「费率」页各有一块预设区，共享同一套预设：

1. 选一个预设 → 点「应用」
2. 填个名字 → 点「保存为预设」，选保存到「通用」还是某家店
3. 内置三个随时可切：**默认 5 条口径** / **模板口径（AE2=0）** / **去 0 元样品**

内置预设只调整「勾了哪些订单类型」，**公式与列标题保持原样**——
套用模板口径不会把你手改过的公式冲掉。自定义预设是完整快照，应用时整体替换。

应用前会自动把当前配置备份到 `config/_backup/`（留最近 20 份），随时能回滚。

> 「模板口径（AE2=0）」对齐模板《V1-净利》的 AE2=0 那一档：
> 订单数 / 成本 / 发单费 只算正常单；买家支付总额与交易手续费 含取消退货、剔 0 元样品。
> 实测套用后与模板**逐条 51 条链接**完全一致。

### 取数快照：算的是哪批数据，说清楚

每次取数结束，会把这一批文件**复制**成一份带标签的快照：

```
data/stores/<店铺ID>/
  meta.json
  inbox/                                       ← 扩展照常写这里（实时）
    orders/  ads/  affiliate/  mapping/        ← 按类型分子目录（靠表头认，不靠文件名）
  snapshots/20261028-1949-a5aca6f3/
    manifest.json                              ← 区间 / 取数时间 / 各文件行数
    订单_....csv   广告_....csv   佣金_....csv
  archive/                                     ← 超 30 份自动压缩归档（不删）
```

- 「开始核算」页有**「用哪次数据」多选清单**：默认勾最新一份，可勾多份**合并计算**
- 报表副标题和「口径」页会写明这批数据的取数时间和区间
- 内容没变 + 5 分钟内重复取数 → 复用同一份，不会堆副本

**为什么需要它**：inbox 是实时的，而核算扫目录时**同类文件只取最新一份**。
你先取 10-01~10-15 算一次，再取 10-16~10-31 算一次，第二次就只有后半段数据了，
但报表名还写着「全部数据」——数字看着正常，其实是错的。快照就是让这件事变得可控。

### 多快照合并：勾哪几份就合并哪几份

「用哪次数据」可以勾多份一起算。合并规则：

| 数据 | 怎么去重 | 重叠时 |
| --- | --- | --- |
| 订单 | 订单号 + SKU | **以取数时间最新的为准**（后取的状态更新，比如后来退款了） |
| 广告 / 联盟佣金 | 整行相同才算重复 | 提示「同商品+同日期但金额不同」，防重复计入 |
| 商品映射 | 不去重，全部合并 | 链接改绑后老 SKU 不能丢 |

> 合并后**会重新统计每个订单的行数**。订单金额是按「订单内 SKU 行数」分摊的，
> 一个订单的 3 行被切在两个快照里时，不重算就会算错分摊基数，
> 买家实付和交易手续费都会偏。修完之后，合并结果与「整份数据单独算」完全一致。

### 数据按店铺分目录管理

- 每家店一个目录，按类型分子目录；文件类型**靠表头判断**，不靠文件名
- **认不出店铺的数据进 `_unknown` 专区**，不参与核算，也不会混进任何一家店
  （旧版本会静默落公共目录，多店铺一起用就乱了，且不报错）
- 选了店铺却没数据时直接报错，不会悄悄拿别的数据算
- 公共目录里的历史遗留文件，用 `python -m scripts.adopt_legacy` 一次性归位

### 自动取数挂了怎么办：手动导数据

扩展这条路依赖平台接口和风控参数，平台一改版就可能断。断了不用干等，
扩展面板里有「**手动导数据**」区，带一个模式开关：

- **陪同导出**（开关开）：点按钮打开店铺页面 → 你在页面上点导出 →
  文件一下载就被接住，自动存进这家店并生成快照
- **只开页面**（开关关）：只帮你打开后台页面，导出后到桌面端「手动导入」上传

桌面端手动导入的流程：

1. 自己进 TikTok 后台，把**订单 / 广告 / 联盟佣金 / 商品表**导出来
2. 在「开始核算」页底部点**「手动导入文件」**，选国家/店铺，上传
3. 文件落进该店铺的 inbox，之后和自动取到的数据**完全一样**地参与核算

上传后会自动认一下这是张什么表（订单表 / 广告表 / 联盟佣金表 / 商品映射表），
认不出来会明确告诉你，不会出现"文件传上去了其实没被用上"的情况。

> 选国家这一步别跳过：费率表是按国家分开的，订单表列名也按国家/语言分开
> （马来站导出的表头跟菲律宾不一样），选错了数字会全错还不报错。

### 「订单表识别」：程序靠这几列判断订单类型

同一页下面还有一栏，列的是订单号、订单状态、取消/退货类型、卖家编码、购买数量……
每个字段同样可以写多个候选标题。它只用来判断「这行算不算取消/退货/未付款」
「属于哪条链接」「按哪个编码对成本」——**金额怎么算不在这里**。

> 老模板把订单服务费并进了「发单费」里（马来西亚 2.37/单 = 3 元×0.61 + 0.54）。
> 程序拆成两个参数：发单费按人民币定价再换汇，订单服务费直接是本地货币。
> 两者都是按订单数算。按模板口径（只算正常单）是 1,682.38 + 496.44 = 2,178.82，与模板逐分一致；
> 现在默认把退货单也算上，服务费为 500.58。

### 发单费与订单服务费的「订单数分摊」

一个订单里常常有多条链接。比如 3 个 SKU 来自链接 A、1 个来自链接 B，
那这个订单对 A 算 3/4 单、对 B 算 1/4 单（按 SKU 行数占比）。
发单费、订单服务费、订单数、买家实付都按这个比例分摊，一个订单的合计永远是 1。

### 直接改配置文件也行

```json
{
  "id": "dispatch",
  "label": "发单费",
  "expr": "orders * params.dispatch_fee_cny * params.cny_to_local",
  "kinds": ["normal", "refunded"]
}
```

`kinds` 不写 = 全部类别；写 `[]` = 这一项不算。
还支持简写形式 `{"base":"gmv","rate":"params.platform_commission"}`，等价于 `gmv × 该费率`。

### 几个关键约定

- **订单数按订单内 SKU 行数平分**：一个订单的分配数合计为 1。
- **买家实付按行分摊**：订单级金额不能按行直接相加，否则三行订单会把实付算成三倍。
- **成本三级解析**：成本表按「卖家编码」精确命中 → 多件装（`-2Pcs` 按基座价×件数）→ 组合装（`+` 拆开相加）。
  都查不到就记进异常页，按 0 计，**绝不猜**。成本表页可以一键「拿订单核一遍」。
- **商品ID 三级定位**：平台 SKU ID（唯一）→ 卖家 SKU → 多件装/组合装拆解后的基座 SKU。

## 四、口径校验

`python -m scripts.validate` 会把引擎结果与主工作簿「净利润」表逐项比对：

| 校验项 | 结果 |
| --- | --- |
| 商品ID 映射 | 1884 / 1887 = **99.84%** |
| 订单数分摊 | **100%**（0 偏差） |
| 买家实付分摊 | **100%**（0 偏差） |
| 成本 | 1893 / 1896 一致 |
| 合计 GMV | 17352.29 对 17352.29（**一致**） |
| 合计净利 | 267.08 对 302.22，差 −35.14 |

那 −35.14 的来源已定位：`MY-J12-5PCS` 三行，原表成本填的是 0，引擎按「5 × 3.84」推出 19.2，
换算后正好 35.14。**是原表漏填，不是算错。**

## 五、取数自动化（进行中）

数据都在你已登录的**战斧浏览器**里。已验证：战斧的 API 与内核直连两条路都走不通
（本地 API 业务端未公开；内核启动需客户端生成的加密参数）。所以走浏览器扩展这条路。

### 已具备：抓包扩展 + 本地桥

```
extension/   浏览器扩展（MV3）：劫持页面 fetch / XHR，把接口调用记录下来
bridge/      本地桥服务    ：接收扩展推送，落盘成可读的接口清单
```

跑起来：

```bash
# 1. 起本地桥
python -m bridge.server        # http://127.0.0.1:8765

# 2. 战斧里加载扩展
#    扩展管理 → 加载已解压的扩展 → 选 extension/ 目录

# 3. 打开店铺后台，正常点一次「导出」
#    抓到的接口写到 data/capture/capture-YYYYMMDD.jsonl
#    去重清单写到 data/capture/endpoints.json
```

`endpoints.json` 就是后续自动取数的目标清单——**先看清真实接口，再写自动化，不靠猜页面结构。**



### 一键运行（推荐用法）

扩展面板上一个按钮就跑完全流程，不用命令行：

```
立即运行：取数 + 算净利
  ↓
订单 / 商品SKU / 联盟佣金 / 广告（已完成任务）
  ↓
POST /run → 本地 Python 核算 → 出 Excel
  ↓
面板直接显示净利、人民币、净利率、商品数、异常数
```

面板上还有：

| 按钮 | 作用 |
| --- | --- |
| 立即运行：取数 + 算净利 | 全流程，随时可点，不等定时 |
| 只算净利（不取数） | 用 `_inbox` 里现有文件重算，改费率/成本后立刻验证 |
| 四个分项按钮 | 单独补某一种数据（也是取完自动核算） |

日期区间、核算国家都在面板上选，面板关闭重开会记住上次的选择。

**定时**：勾选「每周 X 点」或「每月 N 日」，到点自动执行同一套流程
（扩展内 `chrome.alarms` 触发，不需要打开面板）。前提是浏览器和店铺环境开着。

### 全自动取数：五类数据的现状

扩展现已支持**自动执行导出任务**，不用再手工点按钮：

1. 先手工打开一次店铺后台的任意页面（让扩展学到该店铺的公共参数）
2. 点扩展图标 → 选店铺与起止日期 → 点「立即运行」
3. 扩展依次做：创建导出任务 → 轮询导出记录 → 取签名下载地址 → 下载 → 回传到 `data/exports/_inbox/`

| 数据 | 接口 | 状态 |
| --- | --- | --- |
| 订单 | `/api/fulfillment/order/export` → `export_record/get` → `download` | ✅ 全自动 |
| 商品管理 SKU（映射**主来源**） | `/api/v1/product/stock/sku/list`（翻页取全量在售） | ✅ 全自动 |
| 链接资料（映射**补充**） | `/api/v2/insights/seller/ttp/product/sku/list/export` | ✅ 全自动 |
| 联盟佣金 | `/api/v1/oec/affiliate/compass/transaction/detail_list/get` | ✅ 全自动 |
| 广告 | `/oec_ads/shopping/v1/oec/stat/post_product_list_v2` | ✅ 全自动 |

> 广告这一条原先卡了很久：导出接口的 list 只返回 task_id 没有下载地址，
> 一直以为必须先在页面上点「导出」才行。
> 后来抓到页面自己发的请求才发现——**同一个接口不带 `action` 参数就直接返回数据**
> （`data.table_v2`），压根不用走导出流程。
> 抓包方法见下方「抓包模式」，调接口的技能比猜参数可靠得多。

回传的文件按类型分开落盘：

- 订单 / 广告 / 联盟佣金 → `data/exports/_inbox/`（核算引擎直接消费）
- 商品管理 SKU / 链接资料 → `data/mapping/`（只进映射主表，不参与订单核算）

用 `--dir` 指向 inbox 目录即可出报表：

```bash
python -m src.cli --dir data/exports/_inbox --costs "V1-净利  -15.xlsx" --country 马来西亚
```

**为什么必须"在页面上下文里发请求"**：接口依赖 Cookie 和风控参数（`fp`、`X-Tts-Oec-Bsid`），
这些只存在于对应域名的页面里。扩展从真实请求里学一份最新参数再重放，不伪造、不破解。

各数据源的时间参数格式：

| 数据源 | 参数格式 |
| --- | --- |
| 订单 | `time_order_created: ["1590000000000","1590000000000"]`（毫秒） |
| 商品 SKU | `time_descriptor: {"start":"2026-10-01","end":"2026-10-16"}`（日期串，end 开区间） |
| 联盟佣金 | `start_time / end_time`（秒）+ `time_context: "101"`（**少了这个接口不认**） |
| 广告 | 只有查询 `download_task/query`，创建环节待抓 |

### 抓包模式（查新接口时用）

程序自动调接口，是建立在「知道真实参数」的前提上的。平台改版或要接新数据时，
用扩展抓一次真实流量，比猜参数靠谱得多：

1. 在战斧里切到要抓的页面
2. 点扩展面板上的「**① 先点我，再去广告页点一次「导出」**」
   ——监听是全局的，切页不影响；日志会列出各页面上有哪些「导出」按钮
3. 在页面上做你要抓的动作
4. 抓到的请求实时落到 `data/capture/ads_export.jsonl`

> **踩过的坑**：抓包记录只记 URL 不记请求体，等于白抓。
> `chrome.webRequest` 的 extraInfoSpec 里必须带 `"requestBody"`，
> 否则 `details.requestBody` 一直是 undefined。
> 响应样本也截得太狠（原来 6000 字符，很多返回正好被截断，字段看不全只能靠猜），
> 现在放宽到 30000。
